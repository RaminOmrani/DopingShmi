- `serverExternalPackages: ["sharp", "exceljs", "pg"]`.
- `experimental.serverActions.bodySizeLimit: "30mb"` (keep in sync with nginx `client_max_body_size 30m`).

`prisma.config.ts`: schema `prisma/schema.prisma`; it names a migrations path but **`prisma/migrations` does not exist**.
Schema is synced with `prisma db push` (`pnpm db:push`, run by `deploy/update.sh`). Keep schema changes additive
(see [OPERATIONS.md §Gotchas](OPERATIONS.md#13-gotchas)).

Next 16 specifics visible in the code:
- `params` / `searchParams` are Promises (`const { id } = await params`); `cookies()`/`headers()` are async.
- Error boundaries receive `retry` (stable in 16.3; see `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md`).
- `after()` from `next/server` (article view counter), `refresh()` from `next/cache` in some server actions.
- No `middleware.ts` / `proxy.ts`. Auth is checked per page and per route handler.
- `src/instrumentation.ts` `register()` starts the in-process cron (§16).
- No lint step (`next lint` was removed; no ESLint config). Verification = `pnpm typecheck` + `pnpm build` (+ E2E, [TESTING.md](TESTING.md)).

Auth legend: **public** = no login · **user** = `requireUser()` (redirects to `/login`; to `/register` if `!profileDone`
and not admin) · **admin** = `requireAdmin()` (redirects to `/login?next=/admin` or `/panel`). Roles ADMIN and STAFF
both count as admin. `rev N` = `export const revalidate = N` seconds.

## 4. API routes (`src/app/api/`)

All handlers are wrapped in `route()` from `src/lib/api.ts` (except `auth/logout`): `HttpError` → JSON `{error}` with a
Persian message and its status; anything else → 500 «خطای داخلی سرور». `ok()`/`fail()` responses carry
`Cache-Control: private, no-store, max-age=0` and `Vary: Cookie` (commit f03ae98) so no CDN can cache a signed link.
Bodies are validated with `body(req, zodSchema)` (400 with the first Persian zod message).

| route | method | auth | purpose |
|---|---|---|---|
| `/api/auth/otp` | POST `{phone}` | public | Send a 5-digit OTP (stored as sha256(`phone:code`), valid 3 min). Limits: 12/h per IP (memory), 90 s cooldown + 5/h per phone (DB). Blocked user → 403. `devCode` returned only if `sms.provider = mock` and `NODE_ENV ≠ production` |
| `/api/auth/verify` | POST `{phone,code}` | public | `consumeOtp` (5 attempts) → creates the user if new → session → `{next}` (`/admin`, `/panel` or `/register`) |
| `/api/auth/password` | POST `{phone,password}` | public | Password login (students and admin). In-memory limit 8 failures / 15 min per phone and per IP; 350 ms delay |
| `/api/auth/register` | POST `{phone,password≥6}` | public | Sign-up without SMS check (8 / 15 min per IP) → session → `/register` |
| `/api/auth/reset` | POST `{phone,code,password}` | public | OTP + new password → session |
| `/api/auth/logout` | POST | any | Deletes the cookie (plain handler) |
| `/api/me` | GET `?topic=<id>` / `?bundle=<id>` | public | `{user:{name,admin}\|null}`; with `topic` also `{owned, expires, done[]}`, with `bundle` `{owned}` (no-store, Vary: Cookie). Used by Header and `CourseAccess` so public pages stay static |
| `/api/me` | PATCH | user | Profile (name, grade G10/G11/G12/GRAD, major TAJROBI/RIAZI, city, province, school, address, parentPhone/parentSms, class request → classStatus PENDING + classGroupId/classNote); sets `profileDone` |
| `/api/me/password` | POST `{current,password}` | user | Set/change password (`current` required if one exists) |
| `/api/activity/ping` | POST | user | Heartbeat (§9) |
| `/api/videos/[id]/play` | GET `?fresh=1` | user + `canWatch` | Playback info. See [VIDEO.md §2](VIDEO.md#2-server-side) |
| `/api/videos/[id]/progress` | POST `{position,delta,duration?}` | user + `canWatch` | Watch progress + points. See [VIDEO.md §2](VIDEO.md#2-server-side) |
| `/api/videos/[id]/error` | POST | user | Legacy player error endpoint (old open tabs) → `PlaybackEvent` with `sessionId="legacy"` + `[video-error]` log line |
| `/api/playback-log` | POST `{events[1..20], build}` | user | Telemetry ingest. See [VIDEO.md §5](VIDEO.md#5-telemetry) |
| `/api/exams/[id]/start` | POST | user + `canSeeExam` | INTERNAL exams: create/turn result IN_PROGRESS; returns deadline (min(startedAt + duration, endAt)), server now, saved answers, questions without `correct` |
| `/api/exams/[id]/save` | POST `{answers}` | user | Autosave while IN_PROGRESS |
| `/api/exams/[id]/submit` | POST `{answers}` | user | Grade (1/3 negative marking if `negative`). After deadline + 90 s only saved answers count. `Activity.exams++`, `examPoints` |
| `/api/exams/[id]/launch` | POST | user + `canSeeExam` | External exam: upsert result LAUNCHED (source IMPORT), return `externalUrl`; 409 if UPCOMING |
| `/api/pay/start` | POST `{type,id}` | user | `resolveItem`; if Zarinpal disabled or no merchantId → card info `{card:{cards,note,amount,title,pending}}` (503 if card payment also off); else PENDING Payment + `zpRequest` → `{url}` |
| `/api/pay/card` | POST formData `{type,id,tracking≥4,receipt?}` | user | One REVIEW Payment per user+item (method CARD, receipt in `uploads/receipts`); SMS to `site.phone` via `general` |
| `/api/pay/callback` | GET `?pid&Authority&Status` | public | Zarinpal redirect: verify → `fulfill` → redirect `/panel/pay?ok=…` |

## 7. Auth (`src/lib/auth.ts`, `src/lib/api.ts`, `src/lib/otp.ts`)

- Cookie `ds_session` = HS256 JWT `{sub: userId}` (jose), **60 days**, httpOnly, SameSite=Lax, Secure in production unless
  `INSECURE_COOKIE=1`. Secret = `AUTH_SECRET` env, else auto-generated and stored in Setting `auth.secret`.
  Changing the secret logs everyone out.
- `getUser()` is React `cache()`d per request: verifies the JWT, loads user + classGroup, returns null if missing or
  `blocked`. No server-side session list: logout only deletes the cookie; a password change does not revoke other sessions;
  blocking cuts a user off immediately.
- `isAdmin(u)` = ADMIN or STAFF (STAFF = «پشتیبان», full panel access; only ADMIN can change roles). `isClassStudent` = APPROVED.
- Pages: `requireUser({allowIncomplete})`, `requireAdmin()`. API: `mustUser()` (401), `mustAdmin()` (403, unused).
- `clientIp(req)` = `x-real-ip` → first `x-forwarded-for`. Behind the Arvan CDN this is probably the **edge IP** (nginx sets
  `X-Real-IP $remote_addr`, no real_ip config) — reason `arvan.bindIp` stays off. Telemetry uses `telemetryIp` (`ar-real-ip` first).
- Passwords: scrypt, 16-byte salt, `salt:hex` (`hashPassword`/`verifyPassword`, timingSafeEqual). OTP hash = sha256(`phone:code`).
- `normalizePhone` (utils.ts): +98/0098/98/9xxxxxxxxx → `09xxxxxxxxx` or null.
- Flows: (1) phone + password login; (2) OTP login (creates account if new); (3) phone + password sign-up **without phone
  ownership check** (deliberate while SMS is pending); (4) forgot password = OTP + new password. After login: admin →
  `/admin`, incomplete profile → `/register`, else `/panel`.
- Login/OTP limiters are in-memory Maps (reset on restart; per process).

## 9. Points, levels, streaks (`src/lib/points.ts`, `src/lib/constants.ts`)

- `award(userId, reason, refId, amount)`: insert PointLog (unique key → duplicate insert fails → returns false), then one
  transaction increments `User.points` and `Activity(day).points`. Callers pre-check existing PointLogs (heartbeat,
  video progress) so they don't spam failing INSERTs (f03ae98).
- `heartbeat` (POST `/api/activity/ping` every 60 s while the tab is visible, `Heartbeat.tsx`): ignored if < 40 s since
  `lastSeenAt`; adds elapsed (60 s if elapsed > 150 s) to `Activity.onlineSec`; DAILY on first ping of the day; ONLINE per
  10-min block (`refId day:N`) up to `onlineDailyCap`; STREAK when the streak is a multiple of 7.
- `streakOf`: consecutive Activity days ending today or yesterday (60-day lookback). `examPoints` = examBase +
  round(percent/100 × examBonusMax), once per exam. Admin `givePoints` (reason ADMIN; negative allowed).
- Video points: `VIDEO_TIME` per full 300 s block watched, `VIDEO_DONE` once (see [VIDEO.md §2](VIDEO.md#2-server-side)).
  The amount is the setting `points.videoPer5Min` (savePoints; not retroactive); the 300 s block is hardcoded in
  `src/app/api/videos/[id]/progress/route.ts` and refIds are `${videoId}:${n}`, so changing it needs a refId migration plan.
- Levels = periodic-table elements H…Au (79, `ELEMENTS`); threshold for level n = `12·(n−1)²` (`levelThreshold`, `levelOf`); shown by `LevelBadge`.
- Leaderboard: group/all by `User.points`; week = sum of `Activity.points` over 7 days within the user's grade + major.

## 16. Cron (`src/instrumentation.ts` + `src/lib/cron.ts`)

`register()` returns early outside the nodejs runtime and during `phase-production-build`; a `globalThis.__dsCron` guard
prevents double start; first `hourly()` 60 s after start, then every 3600 s, inside the Next server process. `hourly()`:
delete OtpCodes > 24 h; `sub_expiring` SMS for purchases expiring within 3 days (≤ 200/run, sets `remindedAt`); delete
PlaybackEvents > 30 days. Errors log `[cron]`. **More than one Next process = duplicated cron/SMS** → keep pm2 at one fork instance.

## 17. Uploads (`src/lib/upload.ts`)

`saveImage(file, folder, maxWidth)`: ≤ 25 MB, `image/*` only; sharp `.rotate()` → WebP q82 (fit inside maxWidth) + 720 px
thumbnail q74 (`<id>.t.webp`), written to `UPLOAD_DIR/<folder>/<base36time>-<hex>.webp`; returns `/uploads/<folder>/…`.
Folders: photos, teacher, ranks, covers, articles, questions, receipts. `removeUpload(url)` deletes file + thumb (path
traversal guard). nginx serves `/uploads/` from disk; **Next has no `/uploads` route, so uploaded images don't render under
`pnpm dev`** unless something serves `UPLOAD_DIR`. `teacherPhoto(site)` (`src/lib/teacher.ts`): first visible TEACHER photo →
`site.teacherPhoto` if it exists in `public` → `/images/teacher-placeholder.svg`.

## 20. Conventions

- TypeScript strict; Persian JSDoc comments (`/** … */`) above functions, modest density; **all UI text and error
  messages in Persian**; English commit messages; English agent docs.
- Server libs begin with `import "server-only"`. Prisma client: `import { db } from "@/lib/db"` (global singleton in dev);
  types from `@/generated/prisma/client` (not `@prisma/client`).
- Route handlers: `export const POST = route<Ctx>(async (req, { params }) => …)` with `type Ctx = { params: Promise<{ id: string }> }`; zod bodies.
- Admin mutations: `"use server"` files built from `adminAction` + `must` + `revalidatePath`; pages call `requireAdmin()`.
- Formatting helpers (`src/lib/utils.ts`): `faNum`, `toEnDigits`, `fmtInt`, `fmtToman`, `fmtPct`, `fmtDate`, `fmtDayShort`,
  `fmtDuration`, `fmtClock`, `tehranDay()`, `addDays`, `maskPhone`, `cn`, `normalizePhone`. Constants (`constants.ts`):
  GRADES, MAJORS, labels, PROVINCES, CLASS_STATUS_LABEL, ELEMENTS, levelOf.
- Styling: tokens ink, night, deep, cyan, teal, violet, magenta, lime, amber, rose; utilities glass, card, text-gradient,
  text-shine, glow-border, btn(-primary/-ghost/-danger/-sm), input, label, chip, section-title, table-wrap, table.
- In-memory Maps for rate limits/caches assume a **single pm2 process** (a pm2 default; `ecosystem.config.cjs` doesn't pin
  `instances`/`exec_mode`).
- No new dependencies without need; commit `pnpm-lock.yaml`; a dep with install scripts must be added to `onlyBuiltDependencies`.

## 21. Known code caveats (observed, not fixed)

- `access.requireApproval` is dead config.
- No FKs on `Payment.itemId` / `Purchase.paymentId`; `fulfill()` is not transactional (concurrent double approve possible in theory).
- Sign-up creates accounts without verifying phone ownership (intended while SMS is pending).
- ~~Open redirect via `?next=//host`~~ — fixed: `LoginForm.tsx` `sameSitePath()` resolves `next` against `location.origin` and accepts it only if the origin is unchanged.
- `/api/videos/[id]/play` checks `video.published` but not `topic.published`; `/progress` checks neither (only `canWatch`).
- Per-IP limits (register, password login, OTP) use `clientIp()`, likely the CDN edge IP → possible false 429s in rushes
  (unverified; see [TODO.md](TODO.md)).
- Dev mode doesn't serve `/uploads`. Schema deploys via `db push` (no migrations). `update.sh` builds in place (brief outage).
